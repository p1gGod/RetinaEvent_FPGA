# 数据集 v3 与 class2 跨会话可分性（task-12 / M1c）

生成时间：2026-10-29 21:35（Asia/Shanghai）。数据：`row_datas/原始采集数据` 20 条会话；产物：`nn/dataset_v3_w{100,150,200}.npz`；证据：`nn/_evidence/{DATASET3_OK,SEP3_OK}.log`。

## 0. 一句话结论（可判定）

**跨会话 class2 recall = 0.2289 ± 0.1432（3 折：0.0862 / 0.1757 / 0.4247），落在 <0.70 档 ⇒ 按 task-12 判据：先改采集条件，现在不要开训 M2。** 并且 class1 同口径留一会话 LFO 也只有 0.5985 ± 0.1271，说明主要瓶颈是**特征/分类器的会话偏移（session gap）**，不只是 class2 数据条数少；v2 的 0.8297 是同会话时间后半段留出，跨会话掉到 0.23，属于严重高估。

## 1. 背景与根因

- v2 只有 1 条 class2 会话（210102），SEP2 只能做「时间前半段训练 / 后半段测试」，得到 recall 0.8297。该协议里训练和测试来自同一次录制，光照、距离、手的位置、背景完全一致，因此不能代表换一次录制的表现。
- v3 并入 211950、212036 两条新会话后，class2 有 3 条独立录制，才可以做「留一会话」交叉验证。结果：留出的会话 recall 只有 0.0862 / 0.1757 / 0.4247，远低于同会话协议的 0.83。
- 逐折混淆矩阵显示，held 会话的 class2 窗大量被判成 class0/class1（见第 3 节），而不是均匀错误；这是典型的会话级特征漂移 + 类别不平衡（训练集 class2 仅约 137 窗，class0 约 800 窗、class1 约 600 窗，ridge 无类权重，决策边界偏向多数类）。
- class1 对照（16 折 LFO，同样特征/分类器/测试协议）mean recall 0.5985，也低于 0.70，佐证「会话偏移」不是 class2 独有；因此仅继续堆 class2 录像，预计收益有限。

## 3. SEP3 实验设计

- 特征与分类器完全沿用 SEP2：4 通道 30×50 做 5×5 池化 → 240 维 log1p；ridge 最小二乘 λ=1.0；3 类 one-hot。只更换评估协议，保证与 SEP2 可比。
- class2 留一会话 3 折：每折 held 一条 class2 会话；train = 所有 `split=train` 且 `session != held` 的窗（含其余两条 class2 + 全部训练 class0/class1）；test = 固定 test 会话 189 个 class1 窗 + held 会话全部窗（held 的 class0 none 窗与 class2 活动窗都在内）；**class2 recall 只在 held 会话的真实 class2 窗上计算**。
- class1 同口径 LFO：held 依次取 16 条 class1 会话，test / train 规则相同。
- 3 分类 balanced_acc = 出现类别的 recall 宏平均（class0/1/2）。

- **汇总：recall = 0.2289 ± 0.1432，balanced_acc = 0.6627 ± 0.0511**（3 折范围 0.0862~0.4247）。
- class1 同口径 LFO：**recall = 0.5985 ± 0.1271**，balanced_acc = 0.8336 ± 0.0213；16 折范围 0.3621~0.8462（逐折表见证据日志）。
- 会话数缩放诊断：只给 1 条 class2 训练会话（6 折）recall=0.1140；给 2 条（正式 LOO）recall=0.2289，即训练会话翻倍约 +0.1149。
- balanced_acc 看似 0.66~0.73，是因为 class0 recall=1.0（held 会话内 none 窗几乎全对）把宏平均抬高；真正能用的指标是 class2 recall。class1 recall 最高 0.8462，多数 0.4~0.7，同样说明跨会话不稳。

### 4.2 观察

- 最新录制的 212036 留出时 recall 最高（0.4247），最早、离镜头最近且饱和的 210102 最差（0.0862）；方向与「采集条件/距离影响可迁移性」一致，但 3 折样本不足以做因果定论。
- 错误主要落在 class0（none）与 class1（手部开合），而不是随机分散，说明 held 会话的 class2 在 240 维池化特征上更像训练集的负类。
- v2（同会话）0.8297 → v3（跨会话）0.2289，**下降 0.60**；任何拿 v2 曲线做的补录预算都会严重低估难度。

## 5. 判定与「补齐到 0.85」量化

- 判据档位：0.2289 < 0.70 ⇒ **改采集条件**（任务给定规则）。这不是「再多录几分钟」的问题。
- 量化（a）会话数维度（数据驱动，2 点外推）：训练 class2 会话 1→2 时 recall 0.1140→0.2289，按 log2(会话数) 线性外推到 0.85，约需 **84.7 条训练会话**，即当前 3 条之外**再补约 82 条独立会话**；按每会话约 68.3 个 class2 重叠窗折算约 **+5,580 个重叠窗**、按每会话约 4.8 s 折算约 **6.5 分钟等长录像**。成本主要不在时长，而在 82 个不同距离/角度/背景/挥速的场景。
- 量化（b）沿用 v2 学习曲线口径（尾斜率 0.0477/log）：从 0.2289 到 0.85 机械外推需 61,743,979 个重叠窗 ≈ 903,571 条独立会话。**该数字不可用作预算**，它只证明 v2 的同会话曲线不能跨协议外推，必须按会话级评估重新拟合。
- 建议下一步（按优先级）：1）先补 2~3 条独立会话（每段 5 s，不同距离/角度/背景，+137~205 窗），重跑 SEP3 看趋势；2）若仍 <0.70，改采集条件（手完整入画、距离 ≥0.3 m、避免满屏饱和、控制挥速与相位）并改特征（按窗能量归一化、加入时序/运动方向特征）；3）M2 正式训练一律使用会话级留出，不得再用同会话时间切分当验收。

## 6. 风险与局限

- 3 条 class2 会话的 LOO，每折测试 class2 仅 58~74 窗，mean±std 跨折方差大；结论「远低于 0.70」方向可靠，具体数值不宜过细引用。
- 训练集类别不平衡（class2 约 137 窗 vs class0 约 800 窗）；本次有意保持与 SEP2 相同的分类器以做协议对照，未加类权重，因此结果包含不平衡效应，可能低估 class2 可达性能。
- class0 只在训练集；class2 折的 class0 测试样本来自 held 会话自身的 none 窗，balanced_acc 含被抬高成分（见 4.1）。
- 参数组为 assumption，没有独立元数据证据；但不影响会话级 LOO 结论（不依赖 θ/Δ 标签）。
- 窗之间有 50% 重叠（win 100 / stride 50），同一会话测试窗高度相关；这不改变「跨会话不泛化」的结论，但会让单折 recall 的置信区间更宽。
- 本任务未跑正式训练 / 量化（M2 不在范围），也没有改任何 M2 代码。
