## 3. 根因与修复（均为数据管线缺陷，非硬件）

1. **帧数滞回分段在尾部稀疏帧处不退出，产生假长段**（如 192531 曾出现 3.62 s 长段）。旧逻辑只按逐帧事件量 >hi 开段、<lo 且帧数间隔不断来收段，录制尾部零散事件把段尾拖长。修复为**时间跳变断段**：任意相邻帧 times[i]-times[last] > gap_ms(400ms) 即收段（extract_events.py:324-355 detect_segments）。修复后 192531 在 1.2 s 零事件间隙处自然分成 2 段，无需极性切分。
2. **极性主导翻转不是可靠切分特征**。实测段起始 ON 占比可到峰值 0.82~0.87（191620 500ms、191905 1000ms、194508 300/1300/1600/2000ms、192720 1900ms、195624 1200ms 均出现假切点），多数段 ON 比仅 0.3~0.5，无稳定双极性相位。改为保守的**运动包络下凹**切分（extract_events.py:358-411）：段长≥2000 ms 且平滑包络连续≥2 个 100ms 桶 <25% 峰值、切点两侧各≥500 ms 且两侧有≥50% 峰值活动、切点间距≥500 ms 才切。真实 12 文件 **0 刀**，meta 写 split_reason="single"。
3. **label_window 曾硬编码返回类别 1**，导致动作二窗口全被标成动作一 / action2=0。修复为按会话 action 参数标注（extract_events.py:454-466），并在 build_session_windows 传入 sess.action。
4. **np.savez 的 file 参数与 meta 键 file 冲突**（TypeError: savez_compressed() got multiple values for argument 'file'）。改为手写 zipfile + np.lib.format 写 npz（extract_events.py:834-841），保持 meta 键名与契约一致。
5. **count_window 通道顺序与 CHANNELS 相反**（旧实现把 pol=0 放第 0 层，即 OFF 冒充 ON_now），会让 M2 训练与 RTL 特征语义错位。修复为第 0 层=ON（extract_events.py:426-438），并用 npz 自检：ON_now 通道总和 639,907、OFF_now 898,797，与 onoff 统计（动作一+二 ON 639,410 / OFF 898,073，差值为 none 窗口事件）一致；prev 通道 292/292 自检通过。
6. **envelope_cuts 分桶按「每个事件加一次该帧计数」**造成 c² 加权（100 事件帧贡献 10,000），下凹判定被放大。修复为按事件数直接 np.bincount 分桶（extract_events.py:380-383）。
7. **sample_gap / deployment_subset 非重叠窗口公式写成 w×win/stride**，把 244×2 得 488；正确为 w×stride/win（extract_events.py:706-731、756-762），w100 非重叠窗口 = 122 个/类，部署子集 93→46、114→57。报告中一律采用修正后数字。

## 8. 建议 GRID_SHIFT / WIN_MS（stats.json 内已写理由）

- **GRID_SHIFT=3（50×30=1500 格）**：shift=2 → 100×60=6000 格，100ms 窗内大量格为 0（更稀）；shift=4 → 25×15=375 格，手部空间细节丢失。实测 shift=3 时每窗每格 1~2 事件，与 uint16/int8 特征匹配。
- **WIN_MS=100（步进 50）**：会话帧率 9.4~24.2 fps（均值 17.92），100 ms ≈ 1~2.6 帧；200 ms 会把时间分辨率降到 5 Hz 并模糊开合过渡；板端特征更新率 10 Hz，100 ms 窗与之对齐。w150/w200 作为已产出的逃生口，供 M2 对照。

## 9. 遗留风险与下一步

1. 单会话留出统计意义弱；M2 必须补留一参数组交叉验证（见 §6），并报告两组指标。
2. 每类仅 9/10 个循环、122 个非重叠窗，远少于 500；补采前 M2 的结果只能当可行性验证，不能当泛化结论。
3. 事件稀疏（zero_frac≈0.894、每格 p99≈20）：M2 需考虑输入归一化/稀疏卷积或全零通道处理；当前 max=75 未触饱和，量化仍按 int8 SAT_MAX=127。
4. 帧率/事件率跨会话差异大（9.4~24.2 fps），100 ms 窗在低帧率会话里可能只含 1 帧；M2 做跨会话评估时应按会话报告，不要只看合并均值。
5. 包络切分在真实数据 0 刀是保守选择；若补采出现段内 >400 ms 静止，会被时间跳变断段（符合预期）；<400 ms 的短暂静止不会切，可能把两次重复算作一次循环（少计，可接受）。
6. 部署子集 (3,18) 窗口仅 93/114（非重叠 46/57），单独训练不足，见 §7。
7. 输入只读：未修改 row_datas/**、host/app/**、retina_event/**、docs/**；本阶段未跑 Vivado/ModelSim/构建/烧录，未执行 git 写操作。
