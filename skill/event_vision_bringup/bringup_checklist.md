# 事件视觉系统上板 bringup 检查清单

用法：按阶段执行，每阶段写一行证据；前一阶段不通过不进入下一阶段。所有计数器通过控制通道读出，不全依赖示波器。

## 阶段 0：静态检查（上电前）

| 检查项 | 期望 | 失败时先看 | 证据 |
| --- | --- | --- | --- |
| 每个时钟都有 create_clock | 综合/实现报告无 unconstrained 路径 | 时序报告 clock summary | WNS 数值 |
| 异步时钟域有 set_clock_groups | 无跨域时序路径 | 时序报告路径起点终点 | 约束文件行号 |
| 多 bit 跨域用握手或异步 FIFO | 不用 2FF 直接同步总线 | CDC 源码与综合警告 | 模块名 |
| RAM 写块无异步复位 | 综合日志无 RAM is sensitive to asynchronous reset | 综合日志 | 日志行 |
| 复位释放同步到各自时钟域 | 复位撤销不在时钟沿附近 | 复位同步器源码 | 模块名 |

## 阶段 1：上电与时钟/复位

| 检查项 | 期望 | 失败定位 | 证据 |
| --- | --- | --- | --- |
| 心跳计数器 | 每秒递增，读出值随时间变化 | 无变化：时钟或复位 | 两次读数 |
| 时钟锁定状态位 | PLL/MMCM locked 为 1 | 看时钟芯片配置与电源 | 状态寄存器 |
| 复位释放 | 释放后心跳开始，控制通道可读 | 读不到：控制通路 | 读 ID 寄存器 |
| 版本/ID 寄存器 | 与烧录版本一致 | 不一致：烧的是旧比特流 | ID 值 |

## 阶段 2：事件通路逐级计数

在 sensor 接口、FIFO 入口、FIFO 出口、打包器入口、发送器入口各放一个计数器，全部可读。

| 检查项 | 期望 | 失败定位 | 证据 |
| --- | --- | --- | --- |
| 注入已知事件数 N | 各级计数相等 | 第一个不相等的级就是丢点位置 | N 与各级读数 |
| 溢出/丢弃计数器 | 目标速率下为 0 | 非 0：该级带宽不足 | 计数器名与值 |
| 时间戳单调 | 不回退 | 回退：跨域读或 FIFO 顺序问题 | 首个回退时间戳 |
| 空转计数 | 无事件时计数不涨 | 上涨：噪声或误触发 | 计数器值 |

## 阶段 3：包级检查

| 检查项 | 期望 | 失败定位 | 证据 |
| --- | --- | --- | --- |
| magic/version/header_len | 与文档一致 | 全错：字节序或对齐 | 首包十六进制 |
| CRC | 全部通过 | 部分失败：覆盖范围或写回顺序 | 首个坏包序号 |
| 序号 | 连续，回绕符合规则 | 缺口：发送丢包或接收丢包 | seq 缺口位置 |
| 长度 | 不超过 MTU | 超限：分片逻辑 | 最大长度 |
| first/last 成对 | 每帧完整 | 缺尾：发送中断 | 帧号列表 |

离线检查命令：

```bash
python check_stream.py report --events events.csv --packets packets.csv --stats stats.json
```

## 阶段 4：丢帧/丢事件定位（无示波器）

方法：计数器二分。每一步只回答一个问题，避免同时改多个地方。

1) 记录 4 个计数器的起始值：来源计数 C0、FIFO 入口 C1、FIFO 出口 C2、发送完成 C3。
2) 注入固定数量事件 N（例如 10000），读回 4 个值。
3) 找到第一个 C(k+1)-Ck 小于 N 的级；该级就是丢失位置。
4) 缩短观测窗口重复一次，确认是随机丢还是突发丢；随机丢看 FIFO 深度与时钟比，突发丢看背压与仲裁。
5) 若各级计数一致但主机收不到，转到包级：查 magic、CRC、序号、UDP 端口与防火墙。
6) 若丢点随速率变化，先降速率复测，再算余量；余量小于 20% 时不要上长期测试。

时间戳辅助：首个坏包的时间戳与序号能定位到具体窗口；把窗口内的事件数与该窗口的计数器差值对照，可区分「事件丢」与「包丢」。

## 阶段 5：验收

- 连续运行 30 分钟，目标速率下：CRC 失败 0、序号缺口 0、各级丢弃 0、时间戳回退 0。
- 记录：比特流 md5、WNS、资源占用、测试时长、总包数、总事件数、主机收到的数量。
- 证据日志首行写 BRINGUP_OK=1，下面按阶段列证据行；失败时保留原始日志与计数器快照。
- 复测命令与导出脚本一并归档，保证别人能复现。
