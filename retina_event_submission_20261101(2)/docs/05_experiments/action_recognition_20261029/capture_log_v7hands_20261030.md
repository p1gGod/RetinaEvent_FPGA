## 3. 边界如何确定：t_board_ms + dx 中位数

### 3.1 方法（不是秒表）

1. 用 `frames.csv` 首帧 `t_board_ms` 作 t0，把事件时间换成相对毫秒。
2. 按 **100 ms** 分窗，计算每窗事件数 n 与 x 质心 cx；空窗对 cx 线性插值（只为求差分，不参与训练）。
3. 相邻窗差分 `dx[k] = |cx[k] - cx[k-1]|`；只保留 `n > 30` 的窗，避免空窗噪声。
4. 每 **2 s** 取 dx 的中位数；观察活动段与静止段的中位数台阶，确定相位 t0/t1。
5. 边界用 `t_board_ms`（板卡时间）而非墙钟/秒表；t0/t1 记录在 `temp_test/v7_zones.json`。

### 3.2 判定阈值与实测值

【文档】lead 原始口径：**开合 dx 约 6–16，挥手 dx 约 20–38**，相差约 3 倍；cut 无歧义。

【实测】本轮按上述算法独立复算（原始 x 像素 / 100 ms）：

### 3.3 单位口径（必须统一，否则差 8 倍）

【实测】events.csv 的 `x,y` 是 **400×240 原始事件坐标**；转 50×30 网格用 `x >> 3`、`y >> 3`。上面的 dx 是在**原始 x 像素**上算的，所以 5.8–31.3 的单位是「原始像素 / 100 ms」。

`temp_test/v7_zones.json` 的 note_boundary 把同样的数值写成「网格单位」；按代码复算，这个称呼不准确：若换算到 50×30 网格，应再除以 8，即开合约 0.7–1.1 格、挥手约 3.0–3.9 格。数值本身（几倍分离）不受影响，但下游训练/ RTL 若把 dx 当网格单位用，会引入 8 倍量纲错误。**v7 数据构建与后续 winstat/特征 RTL 必须明确采用原始像素口径**（v6 的 `dx/40.0` 归一化也是原始像素口径）。

## 5. mp4 时间轴：容器时间 = 墙钟 × 0.889

### 5.1 实测数字

【实测】ffprobe 结果：

| session | 帧数 | 容器声明 | 容器时长 | 墙钟时长 | 容器/墙钟 |
|---|---:|---|---:|---:|---:|
| v7hands | 6,831 | 30 fps | 227.700 s | 256.160 s | **0.8889** |
| v5probe | 11,516 | 30 fps | 383.867 s（266.667 + 117.200） | 432.108 s | 0.8884 |
| v6clean | 5,174 | 30 fps | 172.467 s | 194.365 s | 0.8873 |

板卡实测有效帧率 26.6–26.7 fps（§1.2），而编码器/容器按 30 fps 写，于是：

```
容器时长 = 帧数 / 30
墙钟时长 = 帧数 / 26.67
容器/墙钟 = 26.67 / 30 ≈ 0.889
```

【推断】这是「容器标称 30 fps、实际采集约 26.67 fps」导致的固定比例，不是录制丢帧（三段均 0 丢帧）。比例随实际帧率有小幅浮动（0.887–0.889），不要把它当精确的 8/9。

### 5.2 使用注意

- 用 `ffmpeg -ss` 按**容器秒** seek：想取墙钟 t 秒，应传 `t × 0.889`；想把容器秒换回墙钟，除以 0.889（约 ×1.125）。
- 需要**逐帧精确**时不要按秒 seek：先从 `frames.csv` 找到目标 `frame_idx`（chunk 内局部号），再用 `select=eq(n,frame_idx)` 或按 `frame_idx/30` 定位；容器第 N 帧就是板卡第 N 帧（同一 chunk 内）。
- 标注工具（host/app/tools/annotator）按 `frames.csv` 的 `frame_idx` / `t_board_ms` 对齐，不受容器时间轴影响；只有「按秒抠图/按秒写标签」的人会中招。
- 报告里的「播放快 12%」与本文 0.889 是同一件事的两种说法（1/0.889 ≈ 1.125，即容器播放比墙钟快约 12.5%）。

## 6. 数据使用规则（v7 及后续）

1. `view` 字段必须保留：A / B / X（transit）。训练、验证、测试分别统计，不得把 B 混入 A 的训练折。
2. transit 段（157–162.5、235–239.5）整段丢弃；不参与训练、不做负样本、不做边界帧。
3. 镜像增强只对 view A 的网格做 `x -> 399 - x`；`cx/dx` 的一阶量符号/方向要同步处理，并写 `aug=0/1`。B 段不做镜像增强。
4. 跨 session 切分：v5probe / v6clean / v7hands 是三个独立 session；禁止把同一 session 的相邻窗随机分到 train/test（时间泄漏）。

6. 原始数据 `records/` 不入库（.gitignore `/records/`）；文档只记录路径、时间、哈希/计数口径，不复制大文件。
