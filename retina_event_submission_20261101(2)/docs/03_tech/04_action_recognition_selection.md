# 动作识别：CNN 选型与 FPGA 资源预算（M0）

> 平台：AMD Artix-7 **XC7A100T-FGG484-2**（正点原子 达芬奇Pro），现有 `retina_event` 工程（纯 Verilog，Vivado 2020.2）。
> 目标：在**不新增外部器件、不新增 I/O** 的前提下，于片内实现 3 类手势 {0=无, 1=握拳→张开, 2=张开→握拳} 识别，结果写入上行数据帧头 `offset 23`。
> 结论分级：**【实测】**= 本机工具报表/上板实测；**【文档】**= 有可点击 URL 来源（见 07/04 调研报告（文件 ../07_调研与审阅/04_动作识别调研_20261029.md，未随包发布））；**【推断】**= 本文按公式计算/工程估算，需综合或上板验证。
> 编写日期：2026-10-29；配套调研与评审：04_动作识别调研_20261029.md（文件 ../07_调研与审阅/04_动作识别调研_20261029.md，未随包发布）。

## 1. 需求与接口约束

### 1.1 分类任务

| 类别 | 语义 | 时间结构 |
|---|---|---|
| 0 | 无动作 / 静止 | 事件率低，极性交替弱 |
| 1 | 动作一：**握拳 → 张开** | 先出现向心收缩、后向外扩张的事件团 |
| 2 | 动作二：**张开 → 握拳** | 与动作一相反的时间顺序 |

类别判定依赖**事件图的时间顺序**，因此输入必须保留至少 2 个时间片（P3 为 4 个），这是 P1 输入取 `2 时间片 × 2 极性 = 4 通道` 的原因【推断】。

### 1.2 部署参数组 TH3/DL18

固定部署参数组：`theta = 3`、`minDelta = 18`（事件判决阈值与去噪最小时间差）。该参数组影响事件率与事件图稠密度，训练集与部署必须使用同一组参数；参数漂移风险见 07/04 §6【推断】。

### 1.3 上行帧头字段（v3，24 B 头）

| 偏移 | 原义 | 新义 |
|---|---|---|
| 0..3 | 魔数 `F0 5A A5 30` | 不变 |
| 22 | `EV_REC_BYTES` | 不变 |
| **23** | **RSVD（规范要求 0x00）** | **动作识别字节** |

`offset 23` 位分配（与 Lead 任务书一致）【文档】：

```
bit7      : VALID      1 = 本帧分类结果有效
bit6..2   : CONF       5 bit 置信度，0..31（0=最低，31=最高）
bit1..0   : CLASS      2 bit 类别，0=无动作，1=动作一，2=动作二，3=保留
```

编码示例：`(1<<7) | (conf<<2) | class`。未启用识别功能时整字节写 `0x00`，与 v3 旧规范前向兼容。

> **接口实现约束（务必遵守）**：P0 上板抓包实测 CRC16/CCITT-FALSE **覆盖整包** `[0..len)`（含 24 B 头），因此 `offset 23` 必须在** CRC 计算之前**写入；若 RTL 现有结构是"先算 CRC 再补头"，需要把分类字节并入 CRC 数据通路，否则上位机整包校验失败【实测/推断，抓包证据见 docs/05_experiments/P0上板验收_20261012/raw/sniff_ack_detail.txt】。

### 1.4 带宽与 I/O

- 分类结果仅 **1 B/帧**，随现有 v3 头回传，不新增端口、不新增 UDP 包【推断】。
- 推理全片内完成，**不访问 DDR3**；DDR3 继续只服务 800×480 显示帧缓存，避免与显示争用【推断】。

## 3. 输入表示：30×50×4 事件图

### 3.1 空间降采样

事件引擎输出 400×240（上屏 ×2）【文档】。按 **8×8 像素池化**：

```
W_grid = 400 / 8 = 50
H_grid = 240 / 8 = 30
```

即空间格 **30 行 × 50 列**；每格统计一个时间片内的 ON/OFF 事件计数，归一化后量化到 int8【推断】。

### 3.2 通道定义（P1）

| 通道 | 含义 |
|---|---|
| c0 | 当前时间片（now）ON 计数 |
| c1 | 当前时间片（now）OFF 计数 |
| c2 | 上一时间片（prev）ON 计数 |
| c3 | 上一时间片（prev）OFF 计数 |

时间片建议 50~100 ms（10~20 Hz 事件图刷新），与 10 Hz 推理节拍对齐【推断】。

2026-10-29 修正：旧表把 now/prev 写反；训练（nn/dataset_*.npz 的 channels 属性）与 RTL（nn_feat）均按 now→prev 顺序实现，以本表为准。【实测】

### 3.3 参数化公式（网格变化时重算）

对输入 `H×W×C`、3×3 卷积、步长 s、无 padding：

```
H_out = floor((H_in - 3) / s) + 1
W_out = floor((W_in - 3) / s) + 1
MAC_conv = C_out × H_out × W_out × C_in × 9
W_bytes   = C_out × C_in × 9                 (int8)
A_bytes   = C_in×H_in×W_in + Σ_l C_out_l×H_out_l×W_out_l
```

**示例：若输入网格改为 16×16×4**（H=W=16）：

| 层 | 输出 | MAC |
|---|---|---:|
| conv1 4→8 s2 | 7×7 | 14,112 |
| conv2 8→16 s2 | 3×3 | 10,368 |
| conv3 16→24 s2 | 1×1 | 3,456 |
| fc 24→3 | 1×1 | 72 |
| **合计** | | **28,008** |

权重降为 4,968 B、激活 1,587 B、计算量仅为 30×50 版的 13.5%【推断】。因此**输入网格必须在 M1 数据集定稿时冻结**（见 07/04 §7 建议修订）。

## 4. 引擎微架构（P1）

### 4.1 数据流

- **输出通道并行**：8 个 lane，每个 lane 对应一个输出通道；lane 内按 `(cin, ky, kx)` 顺序做 3×3×Cin 的 MAC【推断】。
- **权重**：int8，按 lane 打包（8 B/拍）存入 BRAM ROM；同拍广播给 8 个 DSP48E1（25×18 乘法器，int8 符号扩展后直乘）【推断】。
- **激活**：int8 存 BRAM，3 行 line buffer 提供 3×3 窗口；ping-pong 两组 buffer，层间切换【推断】。
- **累加与量化**：DSP 内 32 bit 累加 → 每层一个 per-tensor 移位/缩放（requant）→ ReLU → 饱和到 int8【推断】。
- **控制**：无软核，纯状态机按层遍历；层参数（Cin/Cout/H/W/stride/权重基址）存小 ROM，参数化 Verilog `parameter`【推断】。

### 4.2 算力与时间

```
峰值 = 8 lane × 100 MHz = 0.8 GMAC/s
P1: 208,080 / 0.8e9 = 0.26 ms（理论）
```

考虑 line buffer 填充、层切换、8 lane 在 conv1（仅 8 输出通道）与 conv3（24 通道需 3 组）上的利用率损失，取 **50% 效率**：**≤0.6 ms/次**【推断】。

- 10 Hz 推理：占空比 **0.6%**；
- 30 Hz（33 ms）推理：占空比 **1.8%**；
- 即使 P3（823,968 MAC）也仅 **2.1 ms（50% 效率）**，10 Hz 下 2.1%。

### 4.3 推理节拍建议

动作持续 0.3~1.5 s，**10 Hz 判决**（100 ms 窗口）足够；结果做 3 帧多数表决/置信度阈值后再写 `VALID=1`，降低误触发【推断】。

## 5. 资源预算表（新增引擎）

新增预算为 **P1 引擎（8 lane）**；P2/P3 复用同一引擎，只增加 BRAM 与运行时间【推断】。

| 资源 | 现有已用 | 现有余量 | P1 新增 | 新增占余量 | 加后合计 | 加后占全器件 |
|---|---:|---:|---:|---:|---:|---:|
| Slice LUT | 18,973 | 44,427 | **+2,800** | 6.3% | 21,773 | 34.34% |
| Slice FF | 11,296 | 115,504 | **+3,200** | 2.8% | 14,496 | 11.43% |
| Slices | 6,721 | 9,129 | **+800** | 8.8% | 7,521 | 47.45% |
| BRAM36 Tile | 77.5 | 57.5 | **+7** | 12.2% | 84.5 | 62.59% |
| DSP48E1 | 6 | 234 | **+8** | 3.4% | 14 | 5.83% |
| IOB | 140 | 145 | **0** | 0% | 140 | 49.12% |

**新增预算的组成（推断）**：

| 部件 | LUT | FF | BRAM36 | DSP |
|---|---:|---:|---:|---:|
| MAC 阵列 + 累加/requant（8 lane） | 1,500 | 1,600 | 0 | 8 |
| 激活 ping-pong 存储（19,974 B） | 0 | 0 | 5 | 0 |
| 权重 ROM（5,667 B，含 bias） | 0 | 0 | 2 | 0 |
| 3 行 line buffer + 地址/状态机 | 1,300 | 1,600 | 0 | 0 |
| **合计** | **2,800** | **3,200** | **7** | **8** |

- BRAM 按容量估算（36 Kb = 4,608 B/Tile，不另留余量），端口位宽分割未计入；实际综合可能 ±1~2 Tile【推断】。
- 功耗：推理占空比 <1%，新增逻辑平均功耗估计 **10~20 mW**（静态为主，需 XPE 复核）【推断】。

### 5.1 P2/P3 的额外资源

| 方案 | 权重 | 激活×2 | BRAM36 | DSP | 单次时间（理论/50%） |
|---|---:|---:|---:|---:|---:|
| P1 | 5,667 B | 19,974 B | **7** | 8 | 0.26 / 0.6 ms |
| P2 | 10,967 B | 23,878 B | **9**（+2） | 8 | 0.48 / 1.0 ms |
| P3 | 26,907 B | 39,526 B | **15**（+8） | 8 | 1.03 / 2.1 ms |

即使 P3 也仅占余量 BRAM 的 26%，**片上存储不构成否决项**【推断】。

## 6. P1 / P2 / P3 三候选网络尺寸

> 记号：`k3s2` = 3×3 卷积、步长 2、无 padding；权重为 int8；激活按 int8 单缓冲计。

### 6.1 P1（基准，推荐）

| 层 | 配置 | 输出 H×W | MAC | 权重 B | 激活 B |
|---|---|---|---:|---:|---:|
| input | 30×50×4 | — | 0 | 0 | 6,000 |
| conv1 | 4→8, k3s2 | 14×24 | 96,768 | 288 | 2,688 |
| conv2 | 8→16, k3s2 | 6×11 | 76,032 | 1,152 | 1,056 |
| conv3 | 16→24, k3s2 | 2×5 | 34,560 | 3,456 | 240 |
| fc | 240→3 | 1×1 | 720 | 720 | 3 |
| **合计** | | | **208,080** | **5,616**（bias 51） | **9,987** |

- 激活 ping-pong：`2 × 9,987 ≈ 19,974 B`；权重+bias 5,667 B。
- 单次 0.26 ms 理论 / ≤0.6 ms 实际（8 lane @100 MHz）【推断】。

### 6.2 P2（加宽，精度不足时启用）

| 层 | 配置 | 输出 H×W | MAC | 权重 B | 激活 B |
|---|---|---|---:|---:|---:|
| input | 30×50×4 | — | 0 | 0 | 6,000 |
| conv1 | 4→12, k3s2 | 14×24 | 145,152 | 432 | 4,032 |
| conv2 | 12→24, k3s2 | 6×11 | 171,072 | 2,592 | 1,584 |
| conv3 | 24→32, k3s2 | 2×5 | 69,120 | 6,912 | 320 |
| fc | 320→3 | 1×1 | 960 | 960 | 3 |
| **合计** | | | **386,304** | **10,896**（bias 71） | **11,939** |

- 相对 P1：算力 ×1.86、权重 ×1.94、BRAM +2 Tile、时间 0.48 ms 理论【推断】。
- **什么时候值得上**：P1 在留出集上准确率 < 目标（例如 <90%）且误差主要来自**容量不足**（训练/验证都低）时才启用；若训练高、验证低，应先补数据与增强，而不是加宽【推断】。

### 6.3 P3（4 时间片 8 通道 + 更深，v1 不采用）

| 层 | 配置 | 输出 H×W | MAC | 权重 B | 激活 B |
|---|---|---|---:|---:|---:|
| input | 30×50×8（4 时间片×2 极性） | — | 0 | 0 | 12,000 |
| conv1 | 8→16, k3s2 | 14×24 | 387,072 | 1,152 | 5,376 |
| conv2 | 16→24, k3s2 | 6×11 | 228,096 | 3,456 | 1,584 |
| conv3 | 24→32, k3s2 | 2×5 | 69,120 | 6,912 | 320 |
| conv4 | 32→48, k3s1 | 2×5 | 138,240 | 13,824 | 480 |
| fc | 480→3 | 1×1 | 1,440 | 1,440 | 3 |
| **合计** | | | **823,968** | **26,784**（bias 123） | **19,763** |

- 相对 P1：算力 ×3.96、权重 ×4.77、BRAM +8 Tile、时间 1.03 ms 理论【推断】。
- **什么时候值得上**：仅在"动作一/动作二区分"被证明依赖**更长的时间顺序**（2 时间片无法区分）且 P1/P2 都失败时；P3 的收益主要是时间分辨率，不是空间容量【推断】。

### 6.4 选择逻辑

```
P1 达标（留出集 acc ≥ 目标，动作一/二混淆率可接受）
  ├─ 是 → 采用 P1（默认）
  └─ 否 → 先补数据/增强/调 TH3·DL18
           ├─ 仍欠拟合（train/val 都低）→ P2
           └─ 仅时间顺序不可分 → P3（4 时间片）
```

## 7. 存储布局与初始化

### 7.1 权重 ROM

- 5,616 B int8 + 51 B bias；按层连续存放，层参数表记录 `{cin, cout, h, w, stride, w_base, b_base}`【推断】。
- 初始化用 `$readmemh`（或 `.coe` 生成 BRAM IP），**不要用大 case 语句硬编码**：否则综合时间与 LUT 都会失控【推断】。
- 上电自检：读回权重并算 CRC16，与烧录时记录的期望值比较；不一致则置错误寄存器（上位机可读）【推断】。

### 7.2 激活存储

- 单缓冲 9,987 B，ping-pong 19,974 B → 5 Tile；层间切换只改基址，不搬数据【推断】。
- line buffer：3 行 × 50 列 × 8 通道 = 1,200 B，用分布式 RAM/寄存器【推断】。

### 7.3 时序

- 目标 100 MHz（10 ns）；关键路径：BRAM 读（2 周期）→ DSP 乘加（1~2 级）→ 32 bit 累加 → requant（1 级）⇒ 4~5 级流水，单 lane 吞吐 1 MAC/cycle 可闭合【推断】。
- **待验证**：与现有 800×480 显示/事件通路同布局后是否仍满足 WNS；若失败，先降 lane 数到 6 或时钟到 75 MHz（P1 仍 <1 ms）【推断】。

## 8. 与上位机的契约（摘要）

| 字段 | 位置 | 含义 |
|---|---|---|
| VALID | offset23 bit7 | 1 = 本帧结果有效；上电/未启用时 0 |
| CONF | offset23 bit[6:2] | 0..31 置信度，写 0 表示"低置信"而非"无效" |
| CLASS | offset23 bit[1:0] | 0/1/2，3 保留 |
